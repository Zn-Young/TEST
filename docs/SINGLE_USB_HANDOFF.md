# 单 USB 双摄改造交接

本文件描述下一阶段工作，不表示功能已实现。保留当前 Git 基线，在单独分支适配。

## 已确认输入

HBVCAM-4M2142HD V22，两颗 OV4689，共用一根 USB。用户验证设备 1 使用 DirectShow、MJPEG、3840×1080 时读到 (1080, 3840, 3)。左半帧来自物理左镜头，右半帧来自右镜头。每幅单目图为 1920×1080。编号应可配置，不能永久写死。

## 目标流程

读取并验证配置 → 打开一个相机 → 验证实际帧尺寸 → 原始分辨率切半 → 同时保存同帧的左右图 → 左右分别单目标定 → 有效图像对双目标定 → 保存外参 → 计算并保存立体校正参数。

复用一次成对采集的数据，取消现有两次独立单目采集。继续固定单目内参做 stereoCalibrate。保留左相机为世界坐标系，明确 X_right = R @ X_left + T。

## 实现要求

1. 整个采集只创建一个 VideoCapture。不要把 camera0、camera1 同时设为 1 来重复打开设备。
2. 采集请求 MJPEG、3840×1080；实际图像不符合预期时停止并提示，不能默默缩放后标定。
3. 在原始完整帧中分割左右图，之后再制作预览。所有标定及校正尺寸均为单目 1920×1080。
4. 同一帧保存的左右文件使用同一个编号。依据编号匹配，检查重复、缺失及尺寸。
5. 每次采集使用独立目录或明确的数据集标识，防止历史图片混入。中断时保持已有文件可辨识。
6. 单目筛选分别进行，数量允许不同；双目只使用左右均有效且物理角点顺序一致的图像对。可缓存检测结果，减少重复检测。
7. 显示保存数量、检测成功数量和人工接受数量；有效样本不足时给出清晰错误，不能将空列表传给 OpenCV。最少样本数应作为工程检查，不能宣称仅满足数量就保证精度。
8. 全部正常退出、按键退出和异常路径均释放相机、关闭窗口、检查文件保存结果。
9. YAML 和所有文档使用 UTF-8，读取 YAML 明确使用 utf-8-sig。保留原有板规格，不能未经实物确认猜填参数。
10. 保留内参、畸变、外参、立体校正参数输出，记录使用的数据集、单目图像尺寸、单位和误差指标。

## 配置设计

建议使用 camera_device_id、capture_width、capture_height、capture_pairs 等明确名称。单目宽高可由合成图和分割规则推导，并校验。若保留原参数，必须说明新含义，删除或停用不再读取的参数，避免误导。

如果采用秒为单位的采集间隔，使用 monotonic/perf_counter 等时间计时并明确单位；若仍按循环计数，则明确 cooldown 的单位是循环次数。不要把两者混用。

## 验证与交付

先验证逻辑及配置，再用真实相机确认打开、实际尺寸、左右遮挡对应、保存与退出、角点筛选、有效数量及输出参数。分开报告静态验证、合成数据验证和实机验证。

同帧打包不等于已经证明曝光误差为零；记录厂商同步说明和实际已测范围。完成后同步更新 README、硬件说明、配置和依赖，不要将尚未完成的测试写成通过。
